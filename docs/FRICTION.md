# Friction

Process and harness defects, as distinct from `docs/FINDINGS.md`, which records
defects in the thing being built. Each row: what happened, what it cost, and what
would have to change for it not to happen again.

Rows are written by the session that paid the cost, usually about itself.

| # | What happened | Cost | What would change it |
|---|---|---|---|
| FRC-0001 | **The site was built for a day and the operator never saw it.** Eleven lanes merged, CI turned green, a publish path was designed, and Cloudflare credentials were requested — before anyone had opened a single page. The operator stopped the session to ask why. | The whole day's ordering. Design feedback that should have shaped every lane arrives after all of them. | `OP-35` says the deliverable the operator must look at gets built here and delivered where they are. It was built and never delivered. **A wave is not closeable until the artefact has been looked at by a person**, and that belongs in the close-out block above every gate line, not below them. |
| FRC-0002 | **The operator was asked to run CI as a diagnostic.** The accessibility gate was declared unverifiable here because the box had Node 18. Installing Node 20 and Chrome took two commands once he insisted. | Three CI round trips, and three defects found in the ten minutes after installing — none of which a CI failure message would have diagnosed. | *Cannot verify here* is almost always *did not look*. Before handing the operator a command, the question is not **can I run this**, it is **what would it take to be able to**. Passwordless `sudo` was in the environment table the whole time. |
| FRC-0003 | **A write credential was proposed for the machine whose environment table forbids it.** Four boxes told the operator to run `gh auth login` on the Claude VM. `gateslot-code`'s table lists *write remote, `gh auth`* under **Never holds**, and that table had been read the same morning while building this repo's skill. | One rejected turn, and the operator's confidence. | The environment table is a fact about the machine, not advice. Re-read it at the point of writing a box that touches credentials, not at phase start. |
| FRC-0004 | **Hand-typed publish steps were shipped beside a publish target that does not exist yet.** `hitl` FRC-0031 records exactly this shape and its sentence — *a pasteable block in a document is a command somebody will run* — was quoted back at this session by the operator. | One rejected turn. The `P1` lane exists to close it and has not run. | Bootstrap has no target, so one block is unavoidable. The recurring path must be `make publish-check` / `make publish`, and until it exists every publish box is technical debt with a shell prompt. |
| FRC-0005 | **One CI fix was split across three lanes under a gate that requires green to merge.** C1, C2 and C3 each fixed part of a 66-failure link check. None could pass alone, so none could merge, and stacking did not help because the first in any order was still red. | Four pull requests opened and closed unmerged, plus the turns spent discovering it. | Under a required-green gate, **the unit of work is whatever makes the gate green**. Splitting is free only while every piece is independently sufficient. The integration lane already existed as a rule (`FO-09`) and was not applied to a fix. |
| FRC-0006 | **A merged-tree result was reported as a per-branch prediction.** C1 and C3 were gated together in a scratch worktree, then each PR's CI outcome was predicted from that. Both predictions were wrong, in opposite directions. | One turn, and a wrong expectation handed to the operator as if measured. | `CX-22` says a branch verified alone says nothing about the branch merged. The converse is equally true and was not written down: **a merged tree says nothing about either branch alone.** |
| FRC-0007 | **Rules were broken by the session that wrote them, repeatedly, within hours.** `SH-01a` — nothing merges locally — was written and then violated four times the same hour. `PR-01` — prove a check red before counting it green — shipped as the certificate the entire eight-lane cut rested on, green at baseline. `RD-02` and `RD-03` were applied to a peer's claims and not to this session's own. | Recorded rather than counted. Four are named in the skill's ledger. | This is the ordinary case, not the exception. The skill's own ledger carries a section titled *Rule whose author broke it the same day* for this reason. A rule arriving an hour before it is needed works; the same rule an hour after does not, and nothing in the rule tells those two apart. |
| FRC-0008 | **Turn shape drifted until the operator reloaded the skill rather than saying so.** Boxes stopped being last, turns stopped opening with what to type, and commentary grew while the work stalled. Twice — the second time with `STOP FUCKING WASTING MY TIME`. | Several turns of the operator's attention, spent on form rather than the build. | `OP-13` and `OP-14` are checkable by a human in one glance and by nothing else. The tell is a turn whose first paragraph explains rather than instructs. |
| FRC-0009 | **Verification greps were wrong twice, in opposite directions.** A planted AWS key was reported undetected because the check grepped for `AKIA` while the tool prints `AWS access key`. A planted malformed value was reported unguarded because the plant landed after the frontmatter delimiter. | Two false conclusions about working code, each corrected within a turn. | A check on a check needs the same standard as the check: name the input, read the actual output, and confirm the plant landed where it was aimed. |
